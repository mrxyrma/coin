# Лендинг «Монеты Сбербанк-185» со скролл-анимацией монеты

## Context

Нужен промо-лендинг коллекционных монет к 185-летию Сбера. Ключевая механика: 3D-монета живёт на всей странице как единый объект и при скролле летит по траектории, показанной пунктирными стрелками в макете, поворачиваясь аверсом/реверсом, а в конце укладывается в футляр.

Требования заказчика: **адаптивность** и **быстрая загрузка**. Референс — https://larevoltosa.es/ (разобран: three.js + GLTFLoader + DRACO + GSAP ScrollTrigger со `scrub` + Lenis, одна фиксированная canvas-сцена, вращение модели привязано к `self.progress` скролла, рендер-луп на `gsap.ticker` и ставится на паузу вне вьюпорта).

Проект сейчас — чистый шаблон Vite + React 19 + TS (`src/App.tsx` — демо-страница Vite, подлежит замене).

> **Статус макета: прототип, координаты приблизительные.** Цифры ниже сняты с текущей версии Figma и служат стартовой точкой. Архитектура специально построена так, что при обновлении макета правятся только CSS-позиции `.coin-anchor` и 4 числа `bulge` — код траектории не трогается.

## Техническое решение

**Real-time 3D, не покадровая секвенция.** Секвенция (Blender-рендер 300–600 кадров WebP, `<canvas>` рисует кадр по прогрессу скролла — так сделаны страницы AirPods) даёт картинку 1-в-1, но: 15–40 МБ ассетов, траектория запечена в кадрах, а под мобильный макет (монета по центру вместо левой позиции) нужен отдельный рендер. Это прямо противоречит требованиям «адаптив + быстрая загрузка». Real-time: 1.5–3 МБ ассетов, одна модель на все разрешения, траектория правится в коде.

### Стек

| Пакет | Версия | Зачем |
|---|---|---|
| `three` + `@types/three` | 0.185 | рендер |
| `@react-three/fiber` | 9.x | React 19-совместимый рендерер three |
| `@react-three/drei` | 10.x | `useGLTF`, `Environment`, `useTexture`, preload |
| `gsap` (+ ScrollTrigger) | 3.15 | привязка прогресса к скроллу, `scrub`, `pin` |
| `lenis` | 1.3 | инерционный скролл, синхронизируется со ScrollTrigger |

### Ядро: одна фиксированная сцена + DOM-якоря

```
<div id="app">
  <CoinCanvas />        position: fixed; inset: 0; pointer-events: none; z-index: 1
  <main>                обычный поток, z-index: 2
    <Hero/> <Meaning/> <Appearance/> ... каждая секция содержит
                        <div class="coin-anchor"/> — невидимый блок ровно там,
                        где монета стоит в макете
  </main>
</div>
```

**Главная идея, которая решает адаптивность:** позиции монеты не задаются в 3D-координатах. В каждой секции стоит невидимый `.coin-anchor` — обычный блок, спозиционированный CSS-сеткой ровно по макету (на десктопе в «как выглядит» он слева, на мобиле — по центру; это решает медиазапрос, а не JS). В рантайме читаем `getBoundingClientRect()` всех якорей и переводим экранные пиксели в мировые координаты. Траектория автоматически подстраивается под любой экран, и монета всегда точно попадает в макетную позицию.

Перевод «пиксели → мир» делается настройкой камеры так, чтобы **1 мировая единица == 1 CSS-пиксель** в плоскости z=0:

```ts
// lib/pixelCamera.ts
const D = 1000                                   // camera.position.z
camera.fov = 2 * Math.atan(vh / 2 / D) * (180 / Math.PI)
// тогда: worldX = cx - vw/2 ; worldY = -(cy - vh/2) ; scale = Ø_px / Ø_модели
```

Перспектива при этом сохраняется — при повороте монета корректно ракурсится.

### Система вейпоинтов

```ts
type Waypoint = {
  id: string
  el: HTMLElement          // .coin-anchor секции
  rotX: number             // наклон (рад)
  turnsIn: number          // сколько полуоборотов накопить на подлёте
  bulge: number            // боковой вынос дуги, доля от vw (из стрелок макета)
  visible?: boolean        // в «упаковке» монета скрыта внутри футляра
}
```

Реестр собирается хуком `useCoinWaypoint(ref, cfg)` из каждой секции. На `resize`/`ScrollTrigger.refresh()` пересчитываются мировые позиции и строится `THREE.CatmullRomCurve3` через них с боковыми контрольными точками из `bulge` — получается непрерывная плавная дуга, как на стрелках.

Значения `bulge` из макета (доля vw, знак = сторона): hero→смысл `+0.46`, смысл→как выглядит `−0.18`, как выглядит→уникальность `+0.10`, уникальность→упаковка `+0.21`. На мобиле все `bulge` уменьшаются (× ~0.35), т.к. в мобильном макете монета идёт почти вертикально.

**Привязка к скроллу:** один `ScrollTrigger` на всю страницу, `onUpdate` пишет прогресс в `ref` (никакого React-state — нулевые ре-рендеры). Границы сегментов = момент, когда секция приходит в центр вьюпорта; внутри сегмента `t` проходит через `easeInOutCubic`. Так монета **стоит ровно в макетной позиции**, пока секция читается, и летит между ними на переходах.

**Обе стороны монеты.** Поворот накапливается, а не лерпится между абсолютными значениями:
`rotation.y = scrollTurns * π + uiTurns * π + idleWobble`
`turnsIn` подбирается так, чтобы в «смысл» была видна одна сторона, в «как выглядит» — аверс (в макете подпись «Аверс»), и т.д. Табы «Золото/Серебро» и переключение аверс/реверс по клику добавляют `uiTurns` через `gsap.to` — не конфликтуя со скроллом. Плюс лёгкое покачивание `sin(t)` на паузе (в референсе это `bottleFloatTween`).

**Финал — укладка в футляр.** На сегменте «упаковка → упаковка 2» монета одновременно: уменьшается до Ø206 px, доворачивается по X до ~−52° (сплюснутый эллипс 206×144 из макета = именно этот ракурс), и опускается в углубление ложемента. Параллельно на том же прогрессе анимируется сам футляр (акриловые пластины разъезжаются/сходятся, крышка бука откидывается). Футляры — отдельные GLB, грузятся лениво при подходе к 5-й секции.

### Производительность и загрузка

- Единый RAF: `lenis.raf` вызывается из `gsap.ticker`, R3F переводится на ручной рендер из того же тикера — три RAF-цикла не конкурируют.
- Мастер-`ScrollTrigger` останавливает рендер, когда canvas вне вьюпорта или `document.hidden` (паттерн из референса).
- `dpr={[1, 2]}` на десктопе, `[1, 1.5]` на мобиле; `powerPreference: 'high-performance'`.
- Ассеты: GLB монеты с DRACO + текстуры KTX2/Basis (цель ≤ 2 МБ), HDRI 512×256 `.hdr` (~0.3 МБ; в референсе ровно такой). Футляры — отдельным чанком.
- Первый экран не ждёт GLB: показываем статичный PNG-постер монеты, подменяем на 3D по `onLoad` (кроссфейд).
- JS-бюджет: three+R3F+drei+gsap+lenis ≈ 200–260 КБ gzip.
- Мобайл: упрощённый материал (без `transmission`/анизотропии), меньше источников света, отключённое покачивание.

### Фолбэки

- `prefers-reduced-motion` — движение по траектории выключено, монета просто стоит в позиции текущей секции.
- Нет WebGL — статичные PNG монеты по секциям (те же `.coin-anchor` получают `background-image`).
- Весь текст — обычный DOM, доступен без JS: SEO и скринридеры не зависят от canvas.
- Lenis не должен ломать клавиатурную навигацию и якорные ссылки — проверить Tab/Space/End.

## Производство 3D-ассетов

Модель монеты собирается «дёшево и правильно», без ручного скульптинга всей монеты:

1. Низкополигональный цилиндр (Ø1, толщина 0.12), 128 сегментов, фаска по гурту.
2. **Гильоширование** — тончайшие перекрёстные линии: normal-map 2048–4096 + анизотропная шероховатость. Именно это даёт «живую игру света» при повороте, о которой говорит текст макета.
3. **Ultra High Relief (пеликан)** — нормалкой не продать, силуэт выдаст плоскость. Нужен либо high-poly с displacement, запечённый в ~15–25k трис, либо реальная геометрия рельефа в модели.
4. Два варианта материала: золото и серебро (`MeshPhysicalMaterial`, metalness 1, roughness 0.15–0.3) + HDRI-окружение — без env-map металл не читается.
5. Экспорт GLB → DRACO (геометрия) + KTX2 (текстуры).

### ТЗ дизайнеру на ассеты

Сейчас в макете вместо монеты серые эллипсы #d9d9d9. Запрашивать нужно **3D-модель** — не картинки. Монета крутится, показывает обе стороны и ложится в футляр под произвольным углом; воссоздавать UHR-рельеф пеликана и гильош из плоских изображений долго и результат не совпадёт с их рендерами. Модель у них почти наверняка есть — изображения в макете это её рендеры.

**1. Модель монеты — обязательно**
- Исходник `.blend` / `.c4d` **плюс** экспорт `.glb` или `.fbx`.
- High-poly как есть, ничего не упрощать и не ретополить — оптимизация и запекание на нашей стороне. Задесимированная версия = потерянный рельеф.
- Монета в origin (0,0,0), понятная ось вращения, реальный масштаб.
- Аверс / реверс / гурт — раздельными объектами или хотя бы material slots.
- Золото и серебро: если геометрия одна — достаточно одной модели + параметры двух металлов.

**2. Запечённые текстуры — критично**
Процедурные материалы (ноды Blender/C4D) в GLB **не переносятся** — приедет гладкая болванка. Нужен bake в растр: `normal` + `roughness` + `AO` + `height/displacement`, 4096, PNG 16 бит, развёртка без перекрытий. Отдельно для гильоша (мелкие перекрёстные линии → normal + анизотропная roughness) и для рельефа пеликана.

**3. Футляры**
Обе модели — акриловый «Конструктор» и буковый. Разбитые на объекты: каждая акриловая пластина отдельно, крышка отдельно с понятной осью петли, ложемент отдельно. Единой слепленной геометрией анимацию раскрытия не сделать.

**4. Рендеры-эталоны (2D)**
- Аверс и реверс строго анфас, ортографическая камера, прозрачный фон, 2048+ — эталон для подгонки веб-материала, а также статичный фолбэк для устройств без WebGL и постер первого экрана на время загрузки GLB.
- 3–4 ракурса: 3/4, ребро, монета в футляре.
- Плоский вектор аверса/реверса (SVG/AI) — для UI-элементов.

**5. Свет**
HDRI или студийная схема, в которой они рендерили. Если отдадут `.hdr` — экономит день подбора металла.

**Если 3D-модели не окажется** — минимум: grayscale height-map аверса и реверса (белое = выступает, чёрное = фон), 4096×4096, PNG 16 бит, строго ортогонально, без света и теней. Из неё генерируются displacement/normal. Обычный цветной рендер со светом не подходит — из него высоту не вытащить.

Модель — самый долгий по срокам пункт, запрашивать сразу. Этапы 1–3 идут параллельно на болванке-цилиндре и модель не ждут.

Шрифты SB Sans Display / SB Sans Text у заказчика есть — вопрос закрыт.

## Порядок работ

1. **Каркас и вёрстка.** Токены, сетка, все 8 секций по макету, десктоп + мобайл, весь текст. Монета — пустые `.coin-anchor`. На этом этапе уже есть адаптивная страница с контентом.
2. **Скролл-движок без 3D.** Lenis + ScrollTrigger + система вейпоинтов, а вместо монеты — отладочный DOM-кружок, летящий по кривой. Вся траектория и тайминги настраиваются здесь, дёшево и быстро.
3. **Canvas и временная монета.** Pixel-камера, цилиндр с плейсхолдер-текстурами, подключение к вейпоинтам, накопительное вращение, аверс/реверс.
4. **Продакшн-модель.** Гильош, высокий рельеф, золото/серебро, HDRI, DRACO+KTX2, постер-фолбэк на первом экране.
5. **Футляры и сцена укладки.** Два GLB, ленивая загрузка, финальный сегмент.
6. **Интерактив.** Табы Золото/Серебро, переворот по клику, выноски в «уникальности», кнопки, меню, язык.
7. **Перф и фолбэки.** Пауза рендера вне вьюпорта, dpr-клампы, reduced-motion, no-WebGL, проверка клавиатуры.

## Проверка

- `npm run dev` — пройти скролл сверху вниз: в каждой секции монета должна **стоять точно в макетной позиции** (сверять наложением скриншота на экспорт фрейма из Figma), а между секциями идти по дуге в сторону, указанную стрелкой.
- То же на ширинах 375 / 768 / 1440 / 1920 и при ресайзе на лету (пересчёт якорей без рывка).
- Скролл вверх — анимация должна отыгрываться обратно без накопления ошибки вращения.
- Аверс и реверс видны хотя бы по разу за проход; табы Золото/Серебро переключают материал без сброса позиции.
- Финал: монета садится в углубление футляра, ракурс совпадает с эллипсом 206×144 из макета.
- DevTools: CPU throttling 4×, проверка что FPS не проседает ниже ~50; Network throttling — первый экран рисуется до загрузки GLB.
- Lighthouse (performance/accessibility), реальный телефон (iOS Safari + Android Chrome).
- `npm run build && npm run lint` — чисто.
